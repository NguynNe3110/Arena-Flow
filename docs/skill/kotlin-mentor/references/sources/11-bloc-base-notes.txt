

Flutter Clean Architecture — Base BLoC Design Overview
1. Layered BLoC hierarchy
Every BLoC in the app extends a shared base. There are two levels: BaseBlocDelegate (the real Bloc<E,S> that holds shared dependencies + helper methods) and BaseBloc (adds EventTransformerMixin + LogMixin). base_bloc.dart:9-16


Bloc<E,S> (flutter_bloc)  
  └─ BaseBlocDelegate<E,S>      // shared deps + runBlocCatching + loading/error helpers  
       └─ BaseBloc<E,S>         // + EventTransformerMixin + LogMixin  
            ├─ AppBloc          // @LazySingleton – global app state  
            ├─ CommonBloc       // @Injectable – per-page loading/error hub  
            └─ Feature BLoCs    // @Injectable – HomeBloc, MyPageBloc, ...
Events extend BaseBlocEvent and states extend BaseBlocState — both are empty marker base classes so all events/states share a common type bound. base_bloc_event.dart:1-3 base_bloc_state.dart:1-3

2. Shared dependencies injected into every BLoC
BaseBlocDelegate declares late final fields that every BLoC can use: navigator, appBloc, exceptionHandler, exceptionMessageMapper, disposeBag, and a private _commonBloc. base_bloc.dart:18-23 The commonBloc getter is self-safe: a CommonBloc returns itself, everyone else returns the injected instance. base_bloc.dart:29 add() is overridden to guard against adding events to a closed bloc. base_bloc.dart:31-38

3. runBlocCatching — the core handler wrapper
Almost every event handler runs its logic inside runBlocCatching. This is the single most important method in the base design. It:

calls showLoading() before and hideLoading() after the action (when handleLoading is true),
runs the action,
catches AppException, and if the error should be handled, wraps it in an AppExceptionWrapper and forwards it to CommonBloc via addException,
supports optional lifecycle callbacks: doOnSubscribe, doOnSuccessOrError, doOnError, doOnRetry, doOnEventCompleted,
supports automatic retry (recursively re-invokes itself, decrementing maxRetries). base_bloc.dart:56-123
The loading/error helpers just push events to CommonBloc: showLoading()/hideLoading() add LoadingVisibilityEmitted, and addException() adds ExceptionEmitted and returns a future that completes when the UI finishes handling the error. base_bloc.dart:40-54 Errors from a failed token refresh are always force-handled. base_bloc.dart:125-128

4. CommonBloc — the per-page loading & error hub
CommonBloc is @Injectable() (new per page) and handles three events. common_bloc.dart:10-27 Its state carries appExceptionWrapper, loadingCount, and isLoading. common_state.dart:11-15

_onLoadingVisibilityEmitted maintains a loadingCount so overlapping requests show a single spinner — isLoading is true only when the first request starts and false when the last finishes. common_bloc.dart:31-43
_onExceptionEmitted just stores the wrapper into state so the UI listener can react. common_bloc.dart:45-47
_onForceLogoutButtonPressed clears user data and navigates to login. common_bloc.dart:49-59
5. AppBloc — global singleton state
AppBloc is @LazySingleton() (one instance for the whole app). It holds theme, language, and login status, and handles AppInitiated, IsLoggedInStatusChanged, AppThemeChanged, AppLanguageChanged. app_bloc.dart:7-33 AppInitiated seeds the state at startup from GetInitialAppDataUseCase; theme/language changes persist via use cases inside runBlocCatching. app_bloc.dart:43-75 AppThemeChanged uses the throttleTime() transformer to debounce rapid toggles. app_bloc.dart:19-22

6. Wiring: BasePageState injects everything
BasePageStateDelegate is the glue. For each page it pulls the singleton AppBloc, a fresh CommonBloc, and the page's own bloc from GetIt, then cascades the shared dependencies into them (..navigator, ..appBloc, ..commonBloc, ..exceptionHandler, ...). This is what fills the late final fields in BaseBlocDelegate. base_page_state.dart:15-38 It implements ExceptionHandlerListener, so it can react to token-refresh failures. base_page_state.dart:13-14

The page's build provides both blocs via MultiBlocProvider, then wraps the page in a BlocListener<CommonBloc, CommonState> for errors and a BlocBuilder<CommonBloc, CommonState> for the loading overlay. base_page_state.dart:49-82

7. Communication between BLoC and listener (the key flows)
A) Error flow (BLoC → CommonBloc → listener → handler)
A handler's runBlocCatching catches an AppException and calls addException, which adds ExceptionEmitted to CommonBloc. base_bloc.dart:40-46
CommonBloc stores the wrapper in CommonState. common_bloc.dart:45-47
The BlocListener<CommonBloc, CommonState> in BasePageState fires when appExceptionWrapper changes and calls handleException. base_page_state.dart:56-62
handleException delegates to ExceptionHandler, mapping the exception to a message, and completes exceptionCompleter afterward (which unblocks the addException future in the bloc). base_page_state.dart:98-111
ExceptionHandler.handleException decides the UI: dialog / retry dialog / snackbar based on the exception type & kind. For refresh-token failures it calls listener.onRefreshTokenFailed(). exception_handler.dart:13-57 exception_handler.dart:66-81
onRefreshTokenFailed() (implemented by BasePageState) adds ForceLogoutButtonPressed to CommonBloc, which clears data and routes to login. base_page_state.dart:113-116


Feature Handler (bắt lỗi) → addException → CommonBloc → emit CommonState.appExceptionWrapper → BlocListener trong BasePageState lắng nghe → handleException → ExceptionHandler → hiển thị dialog/snackbar/retry → nếu refresh token fail thì xử lý User → Force Logout → CommonBloc


B) Loading flow (BLoC → CommonBloc → builder)
showLoading()/hideLoading() add LoadingVisibilityEmitted; CommonBloc updates isLoading; the BlocBuilder<CommonBloc, CommonState> in BasePageState shows/hides the overlay. base_bloc.dart:48-54 base_page_state.dart:69-75

C) Feature-local listeners (bloc state → page-local side effects)
Pages override buildPageListeners to attach BlocListeners for their own bloc. In HomePage, two listeners feed the paging controller: one appends loaded users, one forwards the load error — using listenWhen to only react to the relevant field change. This is the pattern for "listener" (side effects) vs "builder" (rebuild UI). home_page.dart:34-54

D) UI → BLoC (dispatching events)
Pages call bloc.add(...) for feature events (e.g. HomePageInitiated, UserLoadMore, HomePageRefreshed) and appBloc.add(...) for global settings. home_page.dart:26-32 home_page.dart:66-68

8. Handler functions pattern (feature BLoC example)
HomeBloc registers each event with on<Event>(_handler, transformer: log()), and each handler wraps its work in runBlocCatching, using emit(state.copyWith(...)) to update state and lifecycle callbacks for shimmer loading / pull-to-refresh completion. Note handleLoading: false here because it uses shimmer loading instead of the global overlay, and maxRetries: 3 enables auto-retry. home_bloc.dart:11-27 home_bloc.dart:61-81

9. Event transformers & logging
EventTransformerMixin wraps rxdart operators — log(), throttleTime(), debounceTime(), distinct(), switchMap(), exhaustMap(), asyncExpand() and combos — so each on<Event> can control concurrency/flow and log the event. log() is the default. event_transformer_mixin.dart:7-48 Globally, AppBlocObserver is set as Bloc.observer to log every bloc's lifecycle across the app. app_bloc_observer.dart:4-12 app_config.dart:20

10. Roles summary
AppBloc — global singleton: theme, language, login; drives MaterialApp. app_bloc.dart:7-13
CommonBloc — per-page hub: loading count, exception surfacing, force logout. common_bloc.dart:10-27
Feature BLoCs — per-page logic delegating loading/errors to CommonBloc via runBlocCatching. home_bloc.dart:10-27
BaseBloc / BasePageState — glue that injects shared deps and wires the CommonBloc listener/builder around every page. base_page_state.dart:23-36
Key mental model: feature BLoCs never talk to the UI about loading/errors directly — they push to CommonBloc, and the BasePageState listener/builder + ExceptionHandler translate that state into dialogs, snackbars, retries, or forced logout. base_page_state.dart:56-82
