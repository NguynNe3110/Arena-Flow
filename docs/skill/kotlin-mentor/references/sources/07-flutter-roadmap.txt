📚 CẨM NANG TRA CỨU: LỘ TRÌNH FLUTTER 35 BÀI (BẢN CHUẨN HÓA - DÀNH CHO ANDROID DEV)
(Tuân thủ tuyệt đối Meta Rule - Tầng 1: Foundation Rules & Tầng 2: Learning Rules)

🏗️ GIAI ĐOẠN 1: Flutter Foundation (Nền tảng UI)
Mục tiêu: Hiểu cơ chế vẽ UI của Flutter, đặc biệt là những khái niệm Jetpack Compose không có. Chỉ dùng setState ở giai đoạn này.
Bài 1: Widget Tree & Element Tree
Là gì: Cấu trúc cây lồng ghép của các Widget. Mọi thứ trong Flutter đều là Widget. Flutter tách biệt rõ ràng giữa Widget (cấu hình bất biến) và Element/RenderObject (đối tượng vẽ thực tế).
Map Android: Tương tự cây Composable trong Compose, nhưng Flutter có thêm tầng Element Tree để tối ưu việc tái sử dụng.
Bài 2: StatelessWidget
Là gì: Widget không thay đổi trạng thái sau khi được build. Nhận dữ liệu từ bên ngoài (constructor) và chỉ vẽ ra UI.
Map Android: @Composable function chỉ nhận tham số và không chứa remember { mutableStateOf() }.
Bài 3: StatefulWidget
Là gì: Widget có thể thay đổi giao diện theo thời gian. Nó đi kèm với một State object riêng biệt để lưu trữ dữ liệu.
Map Android: @Composable function có sử dụng remember để lưu giữ state.
Bài 4: setState()
Là gì: Hàm gọi bên trong State của StatefulWidget để báo cho Flutter biết "dữ liệu đã thay đổi, hãy vẽ lại UI".
Map Android: Việc gán giá trị mới cho biến state trong Compose (ví dụ: count++), Compose tự động phát hiện và recompose.
Bài 5: BuildContext ⚠️ (Quan trọng nhất)
Là gì: Một "handle" (tay cầm) tham chiếu đến vị trí của widget này trong Widget Tree. Dùng để tìm kiếm dữ liệu từ các widget cha (Theme, Navigator, Bloc...).
Map Android: Compose không có khái niệm này. Nó gần giống với việc bạn cần biết "mình đang ở đâu trong cây UI" để lấy LocalContext.current trong Compose.

🔄 GIAI ĐOẠN 2: State Management với BLoC (Pattern & Package)
Bài 6: Cú pháp cốt lõi flutter_bloc (Nhập môn)
Làm quen với cách Bloc "sống" trong Widget Tree. Map 1:1 với cách Compose dùng ViewModel.
Nội dung:
BlocProvider: Cách tạo và "phát sóng" Bloc cho cây Widget con. (Map: viewModel()).
BlocBuilder: Cách lắng nghe State để vẽ UI. (Map: collectAsState()).
BlocListener: Cách lắng nghe State để xử lý tác dụng phụ 1 lần (Toast/Nav). (Map: LaunchedEffect + SharedFlow).
context.read<T>() vs context.watch<T>(): Khi nào cần đọc 1 lần (bắn Event), khi nào cần nghe liên tục (vẽ UI).
Thực hành: Viết lại màn hình Login thuần túy bằng các widget này để quen tay.
Bài 7: BlocListener Nâng Cao & BlocConsumer
Tối ưu hóa việc xử lý Side Effect và gộp Widget để code gọn hơn.
Nội dung:
listenWhen & buildWhen: Bộ lọc giúp tránh rebuild UI hoặc hiện Toast lặp lại không cần thiết.
Bug "Consume Event": Cách reset cờ State sau khi đã xử lý Side Effect.
BlocConsumer: Widget kết hợp sẵn BlocListener và BlocBuilder.
Thực hành: Xử lý hoàn hảo 3 trạng thái: Loading (vẽ UI) -> Success (chuyển màn hình) -> Error (hiện SnackBar).
Bài 8: MultiBlocProvider & Bloc Lifecycle
Quản lý nhiều Bloc trong 1 màn hình và hiểu vòng đời của chúng.
Nội dung:
MultiBlocProvider: Cung cấp nhiều Bloc cùng lúc, tránh lồng BlocProvider quá sâu.
Vòng đời Bloc: Bloc được tạo khi create chạy, bị đóng (close()) khi Widget bị dispose.
BlocProvider.value: Truyền Bloc đã có sẵn (dùng khi chuyển màn hình mà muốn giữ nguyên Bloc).
Thực hành: Màn hình có 2 Bloc (LoginBloc + ThemeBloc). Dùng MultiBlocProvider và debug xem khi nào Bloc bị close().
Bài 9: Bloc-to-Bloc Communication
Cách các Bloc giao tiếp mà không vi phạm luồng 1 chiều (Phần khó nhất).
Nội dung:
Tại sao cần? AuthBloc logout → CartBloc cần xóa giỏ hàng.
Cách 1 (Trong UI): Lắng nghe Bloc A, rồi add() event vào Bloc B.
Cách 2 (Trong Bloc): Inject Bloc A vào Bloc B, nghe stream.
Cách 3 (Chuẩn Clean Arch): Giao tiếp gián tiếp qua Repository/UseCase chung.
Thực hành: Viết AuthBloc và CartBloc. Khi logout → CartBloc tự clear.
Bài 10: Repository Pattern + Bloc
Ghép nối tầng Presentation (Bloc) với tầng Data (Repository).
Nội dung:
Inject Repository (Interface ở Domain) vào constructor Bloc.
Bloc gọi repository.getData() → nhận kết quả → emit State.
Error Handling: Repository throw Exception → Bloc try-catch → emit State lỗi.
Thực hành: Viết AuthRepository (giả lập API) → Inject vào LoginBloc → Gọi login.

🛡️ GIAI ĐOẠN 7: Error Handling & Production UI/UX
Mục tiêu: Xử lý lỗi chuẩn Tầng 2 và hoàn thiện vỏ bọc ứng dụng chuyên nghiệp.
Bài 27: Custom Exception & Try-Catch
Là gì: Tự viết các class Exception (NetworkException, ServerException, CacheException). Dùng try-catch ở tầng Data/Domain, throw lên Presentation.
Map Android: Tương tự Result<T> / sealed class error handling.
Bài 28: Mapping Error to UI State
Là gì: Bloc nhận Exception, convert thành State Error(message) để UI hiển thị. KHÔNG dùng Either, Result (tuân thủ Tầng 2).
Map Android: Tương tự UiState.Error(message) trong Compose.
Bài 29: Theme System & Dark Mode
Là gì: Định nghĩa màu sắc, typography, shape chung cho toàn bộ ứng dụng.
Map Android: MaterialTheme trong Compose.
Bài 30: Responsive Design
Là gì: Làm UI thích ứng với nhiều kích thước màn hình (Phone, Tablet, Desktop). Dùng LayoutBuilder, MediaQuery.
Map Android: WindowSizeClass trong Compose.
Bài 31: Animation (Implicit & Explicit)
Là gì: Implicit (tự động khi thay đổi giá trị, ví dụ: AnimatedContainer) và Explicit (kiểm soát từng khung hình bằng AnimationController).
Map Android: animate*AsState và animate* (với Transition) trong Compose.
Bài 32: Logging
Là gì: Ghi log để debug (dùng package logger).
Map Android: Timber.


🚀 GIAI ĐOẠN 8: Project Thực Chiến & UPGRADE SIGNAL (Mở khóa Tầng 3)
Mục tiêu: Làm project thực tế và chỉ khi phát ra "Upgrade Signal", bạn mới được mở khóa các thư viện Production.
Bài 33: Project Thực Chiến - Phần 1 (Feature List & Detail)
Là gì: Xây dựng app hoàn chỉnh (ví dụ: App tin tức) với luồng: UI → Bloc → UseCase → Repo → Dio. Áp dụng GoRouter, GetIt, Theme.
Map Android: Tương tự bài tập tổng hợp Android.
Bài 34: Project Thực Chiến - Phần 2 (Offline-First & Auth)
Là gì: Thêm tính năng offline cache (Drift/Hive), login với Interceptor tự gắn token, xử lý refresh token.
Map Android: Tương tự bài thực chiến Android với Room + Auth.
Bài 35: 🟢 UPGRADE SIGNAL - Tự động hóa & Production
Là gì: CHỈ MỞ KHÓA KHI BẠN PHÁT TÍN HIỆU. Giới thiệu freezed + equatable (thay thế copyWith thủ công), json_serializable (thay thế fromJson thủ công), injectable (thay thế GetIt manual). Giải thích chúng đã tự động hóa phần nào của Tầng 2.
Map Android: Tương tự việc chuyển từ code tay sang dùng KSP / Hilt / Moshi Codegen trong Android.
